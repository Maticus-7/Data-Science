CASO 00 · FUNCIONES AUXILIARES · LA REJILLA OPERATIVA

Dos funciones que se aplican a las cuatro pruebas

Antes de ver una sola prueba, definimos un lenguaje común: la rejilla de lectura del p-valor (función interpretar_p) y un bloque uniforme de reporte (función imprimir_resultado). Si el alumno aprende este patrón, va a leer cualquier p-valor con el mismo criterio el resto de su vida profesional.

Pieza pedagógica clave de toda la notebook. Estas dos funciones son la pieza pedagógica más importante del cuaderno: no son glamorosas, pero garantizan que el alumno escuche EL MISMO mensaje cuatro veces. Sin ellas, cada prueba terminaría con un texto distinto y la rejilla de lectura no se internalizaría.
CÓDIGO COMPLETO · interpretar_p()
La rejilla de evidencia · convierte un número en una decisión
def interpretar_p(p_valor, alpha=0.05):
if p_valor < 0.001:
nivel = "Evidencia MUY FUERTE contra H₀"
elif p_valor < 0.01:
nivel = "Evidencia FUERTE contra H₀"
elif p_valor < 0.05:
nivel = "Evidencia SIGNIFICATIVA contra H₀"
elif p_valor < 0.10:
nivel = "Evidencia MARGINAL (al borde)"
else:
nivel = "Datos COMPATIBLES con H₀"
decision = "RECHAZAR H₀" if p_valor < alpha else "NO rechazar H₀"
return {"p_valor": p_valor, "alpha": alpha,
"nivel": nivel, "decision": decision}

DECISIONES TÉCNICAS
Por qué esta función y no otra
¿Por qué cinco categorías y no tres?
Tres ("significativa / no significativa / al borde") es lo mínimo, pero pierde información. Cinco te permite distinguir fuerza de evidencia, no solo decisión. Para reportes ejecutivos: "p < 0.001" pesa más que "p = 0.04" aunque ambos rechacen H₀.
Alternativa descartada: usar Bayes Factor en lugar de p-valor categórico. Más correcto técnicamente, pero rompe el flujo conceptual de la sesión.
¿Por qué devolver dict en vez de imprimir directo?
Si imprime directo, no se puede reusar el resultado. Devolviendo dict, otra función (como imprimir_resultado) puede formatearlo en una tabla, en LaTeX para un paper, o exportarlo a JSON. Es buena práctica general: separar lógica de presentación.
¿Por qué alpha como parámetro y no hardcoded?
Hay disciplinas donde α = 0.01 (clínica), donde α = 0.10 (exploratorio), donde α se corrige por Bonferroni. Hardcodear 0.05 obliga a duplicar la función. Mejor: default razonable, override fácil.

Preguntas y errores típicos
PREGUNTA SOCRÁTICA
"¿Qué hubiera pasado si pongo alpha=0.10?" Cambiá el default a 0.10 en vivo y mostrá cómo casos que antes decían "NO rechazar" pasan a "RECHAZAR". Pregunta de continuación: "¿es esto trampa, o legítimo?". Discusión: depende del costo del error tipo I en el dominio.
PREGUNTA SOCRÁTICA
"¿Por qué no devuelve un booleano (rechazar / no rechazar)?" Porque pierde la magnitud de la evidencia. Un booleano colapsa "p = 0.049" y "p = 1e-10" al mismo valor, cuando el segundo es muchísimo más fuerte.
ERROR TÍPICO 1
El alumno escribe if p_valor < 0.05 al revés y obtiene "rechazar" cuando p es alto. Cómo prevenir: insistí 3 veces en la regla: "p chico = datos raros bajo H₀ = rechazar H₀". Es contraintuitivo porque "chico = malo".
ERROR TÍPICO 2
Confundir "evidencia MUY FUERTE contra H₀" con "H₀ es definitivamente falsa". Recordá la frase: "el p-valor no es la probabilidad de que H₀ sea verdadera; es la probabilidad de los datos asumiendo H₀ cierta". Repetilo cada vez que aparezca.
ERROR TÍPICO 3
"Si p ≥ 0.05, H₀ es verdadera". NO. Solo "no hay evidencia para rechazarla". La diferencia se ve clara en el Caso 02 (z 2 proporciones) cuando hacemos el análisis de poder y descubrimos que no rechazar no es lo mismo que aceptar.
VARIANTES Y EXTENSIONES
Cómo adaptarla a otros contextos
Para reportes ejecutivos · agregar emoji o color
decision = "🟢 RECHAZAR H₀" if p_valor < alpha else "🔴 NO rechazar"
En reportes a directorio que no leen estadística, un semáforo visual ayuda. En clase mantenemos sin emoji para que el alumno se acostumbre a la lectura formal.

Si vas a hacer 20 tests al α=0.05, esperás 1 falso positivo por azar. Bonferroni divide α por el número de tests para controlar el error global. Se discute más en el Caso 03 (ANOVA vs t-tests múltiples).
CASO 01 · IC PARA PROPORCIÓN · ESTIMACIÓN HONESTA

Tres líneas con statsmodels que reemplazan media página de fórmula manual

El caso 01 es el más simple del cuaderno: una sola función (proportion_confint), tres parámetros y un resultado interpretable. Es el lugar ideal para enseñar el patrón "función de scipy/statsmodels recibe datos crudos + parámetros, devuelve resultado".

Lo que hace la celda principal. Calcula el IC95% para la proporción usando el método Wald (aproximación normal). Es el método clásico, el que se enseña en estadística básica. Funciona bien cuando n·p̂ ≥ 10 y n·(1−p̂) ≥ 10, condiciones que en BancoSur (n=5000, p̂=0.028) se cumplen holgadamente: n·p̂ = 140, n·(1−p̂) = 4860.
CÓDIGO COMPLETO · IC95% para proporción
Tres líneas que responden la pregunta del directorio
from statsmodels.stats.proportion import proportion_confint
# Datos del caso · 5.000 auditados, 140 en default
n_audit = 5000
defaults = 140
p_hat = defaults / n_audit # 0.028 = 2.8%
ic_inf, ic_sup = proportion_confint(
count = defaults,
nobs = n_audit,
alpha = 0.05,
method = "normal",
)
print(f"IC95% Wald: [{ic_inf:.4f}, {ic_sup:.4f}]")
# → IC95% Wald: [0.0234, 0.0326]

DECISIONES TÉCNICAS
Los 6 métodos posibles de proportion_confint, y por qué elegimos "normal"
method="normal" · Wald · el clásico
Es p̂ ± z·√(p̂(1−p̂)/n). Lo que enseña cualquier libro intro. Válido cuando np ≥ 10 y n(1−p) ≥ 10.
Limitación: con p̂ muy cercano a 0 o 1, puede dar IC con límite negativo (sin sentido para una proporción). En este caso p̂=0.028, no llega a romperse.
method="wilson" · más robusto · default moderno
Corrige el problema de Wald con p cercano a los extremos. Nunca sale del rango [0, 1]. Es el método recomendado por la mayoría de estadísticos hoy.
Por qué no lo usamos: queremos coincidir con la fórmula del deck (slide 17, que muestra explícitamente el Wald). Para enseñar la fórmula manual, Wald es más transparente.
method="beta" · Clopper-Pearson · exacto
Método "exacto" basado en la distribución Binomial directamente. NO aproxima. Siempre tiene cobertura ≥ 95%.
Cuándo usarlo: con n muy chico (n < 30) o p muy extremo (p < 0.01). Es conservador (IC más anchos que Wald).
Otros: "agresti_coull", "jeffreys", "binom_test"
Variantes intermedias entre Wald y Wilson. Excelentes técnicamente, raramente vistos en clases de negocio.
TIPS PARA EL AULA
Preguntas y errores típicos
PREGUNTA SOCRÁTICA
"¿Qué pasa con el IC si auditamos 50.000 créditos en vez de 5.000?" Cambialo en vivo, recalculá. El IC se cierra a aproximadamente [0.0265, 0.0295]. Pregunta de continuación: "¿el histórico Q4 (2.5%) seguiría cayendo dentro?". Conclusión pedagógica: con n suficiente, lo que antes era "ruido" se vuelve "señal real".
PREGUNTA SOCRÁTICA
"¿Por qué pasamos count y nobs y no directamente p̂ = 0.028?" Porque la incertidumbre depende de N. Un 2.8% sobre 100 créditos tiene un IC enorme; sobre 50.000, un IC angosto. La función necesita saber el N para calcular el SE.
ERROR TÍPICO 1
El alumno escribe alpha=0.95 esperando 95% de confianza. Resultado: obtiene un IC del 5%. Cómo prevenir: repetí "α es lo que QUEDA AFUERA del IC, no lo de adentro. IC95% → α=0.05, no 0.95".
ERROR TÍPICO 2
Olvidar que count debe ser un entero. Si pasás un float (por ejemplo, count = 5000 * 0.028 = 140.0), statsmodels generalmente lo acepta, pero en versiones viejas tira warning. Mejor castear con int().
ERROR TÍPICO 3
Decir "hay 95% de probabilidad de que el verdadero default esté entre 2.34% y 3.26%". FALSO. La interpretación correcta: "si repitiéramos la auditoría muchas veces, el 95% de los IC construidos contendrían al verdadero default". El verdadero default es una constante; lo que varía es el IC.
VARIANTES Y EXTENSIONES
Mismo patrón, otros casos de negocio
Retail · IC para tasa de conversión

Mismo flujo, distinta interpretación. Para conversión web, Wilson es preferible porque las tasas suelen ser bajas (1-5%) y Wald se desestabiliza.
Salud · IC para tasa de readmisión hospitalaria

En contexto clínico, α=0.01 y método exacto (beta = Clopper-Pearson) son norma. Decisiones que afectan pacientes piden más rigor.
CASO 02 · TEST z DE 2 PROPORCIONES + ANÁLISIS DE PODER

Dos funciones de statsmodels resuelven todo el A/B test

El caso más rico del cuaderno: combina el test formal (proportions_ztest) con el análisis de poder (NormalIndPower). El alumno aprende que reportar "no rechazo H₀" sin reportar poder es deshonesto: quizás no hay efecto, o quizás faltó muestra.

Por qué este caso es el más importante. Cubre el patrón que los alumnos van a usar más en su carrera profesional: A/B testing con proporciones. Si solo aprenden una prueba de la sesión, que sea esta. El análisis de poder al final es lo que distingue un análisis serio de un test casero.
CÓDIGO COMPLETO · z test unilateral
Datos · llamado · interpretación
import numpy as np
from statsmodels.stats.proportion import proportions_ztest
# Datos del A/B test
n_Q4, x_Q4 = 4800, 120 # control · 2.5% default
n_Q1, x_Q1 = 5000, 140 # tratamiento · 2.8% default
z_stat, p_valor_z = proportions_ztest(
count = np.array([x_Q1, x_Q4]), # Q1 primero · luego Q4
nobs = np.array([n_Q1, n_Q4]),
alternative = "larger", # cola derecha · "Q1 mayor"
)
print(f"z = {z_stat:.3f}") # → z = 0.928
print(f"p = {p_valor_z:.4f}") # → p = 0.1768

Qué hace cada argumento de proportions_ztest

CÓDIGO · ANÁLISIS DE PODER (segunda parte)
¿Cuánto n necesitamos para detectar Δ=0.5pp?
from statsmodels.stats.proportion import proportion_effectsize
from statsmodels.stats.power import NormalIndPower
p_base = 0.025
p_alt = 0.030 # 0.5pp arriba
effect_h = proportion_effectsize(p_alt, p_base) # Cohen's h
power_calc = NormalIndPower()
# 1. Despejar el PODER dado n=5000
poder = power_calc.solve_power(
effect_size = effect_h,
nobs1 = 5000,
alpha = 0.05,
ratio = 1.0,
alternative = "larger",
)
# 2. Despejar el N necesario para poder=0.80 (omitiendo nobs1)
n_necesario = power_calc.solve_power(
effect_size = effect_h, alpha = 0.05,
power = 0.80, ratio = 1.0, alternative = "larger",
)
DECISIONES TÉCNICAS
Por qué unilateral, por qué effect_size, por qué NormalIndPower
¿Por qué unilateral ("larger") y no bilateral ("two-sided")?
La hipótesis del COO es DIRECCIONAL: "el default subió". No le importa si bajó. El test debe reflejar esa dirección. Si fuera bilateral, el p-valor sería 2x mayor (≈0.35) porque incluye también la cola izquierda. Que no nos interesa.
Cuándo elegir bilateral: cuando la pregunta es "¿hay diferencia en cualquier dirección?". Por ejemplo, comparar dos modelos sin tener priors sobre cuál será mejor.
¿Qué es Cohen's h (effect_size)?
Transformación arcoseno de las dos proporciones: h = 2·asin(√p₁) − 2·asin(√p₂). Estandariza la diferencia para que sea comparable entre estudios. Reglas de bolsillo: |h| ≈ 0.2 chico, 0.5 mediano, 0.8 grande. Para Q4 vs Q1: h ≈ 0.020 (efecto MUY chico).
Alternativa: usar directamente la diferencia (p₁ − p₂). El problema es que 0.5pp sobre base de 2.5% es mucho más grande que 0.5pp sobre base de 25%, pero la diferencia absoluta es la misma. Cohen's h normaliza.
¿Por qué NormalIndPower y no TTestIndPower?
NormalIndPower usa el test z basado en distribución Normal. Es lo correcto para proporciones con n grande. TTestIndPower es para medias con varianza desconocida (test t), más conservador.
¿Qué hace solve_power cuando omitís un argumento?
Es una API "despejar la incógnita": la función tiene 4 variables ligadas (effect_size, nobs1, alpha, power). Le pasás 3, y despeja la 4ta. Si no pasás power, calcula poder. Si no pasás nobs1, calcula N necesario.
TIPS PARA EL AULA
Preguntas y errores típicos
PREGUNTA SOCRÁTICA
"¿Qué pasa si cambio alternative='larger' a 'two-sided'?" Hacelo en vivo. El p-valor se duplica de 0.177 a 0.354. Pregunta de continuación: "¿en qué caso real sería honesto reportar el bilateral?". Respuesta: solo si no teníamos hipótesis previa sobre la dirección.
PREGUNTA SOCRÁTICA
"Si el poder con n=5000 es solo 27%, ¿qué significa eso?" Significa que aunque la diferencia EXISTA, solo 27 de cada 100 veces el test la detectaría. 73 de cada 100 veces, el test diría "no rechazar" aunque el deterioro fuera real. Por eso "no rechazar" no es "aceptar".
ERROR TÍPICO 1
Olvidar el ORDEN de count y nobs. Si ponés Q4 primero pero usás alternative="larger", estás testeando "Q4 > Q1" (deterioro al revés), y el z viene negativo y el p ≈ 0.82. Cómo prevenir: ANTES de llamar a la función, escribí en un comentario "primer elemento = el que H₁ dice que es mayor".
ERROR TÍPICO 2
Confundir effect_size de Cohen's h con la diferencia absoluta de proporciones. Cohen's h NO es 0.5pp ni 0.005. Es ~0.020 (la transformación arcoseno reduce el número porque trabaja en otra escala). No le pidas al alumno que lo calcule a mano; deferí a proportion_effectsize.
ERROR TÍPICO 3
Reportar al directorio "el test dice que no hay deterioro" cuando lo correcto es "el test no detecta deterioro, pero el poder es bajo (27%)". La primera frase es deshonesta y operacionalmente peligrosa.
VARIANTES Y EXTENSIONES
Otros A/B tests con el mismo flujo

CASO 03 · ANOVA DE UN FACTOR + POST-HOC TUKEY HSD

Dos funciones de dos librerías distintas, una sola pregunta

ANOVA responde "¿alguna media es distinta?" pero NO dice cuál. Tukey HSD responde "¿cuál(es)?" controlando el error de comparaciones múltiples. Este caso es donde el alumno aprende a NO hacer "todos contra todos" con t-tests.

Particularidad técnica de este caso. Estamos haciendo ANOVA sobre datos 0/1 (Bernoulli), no sobre cantidades continuas "naturalmente" normales. Funciona porque el TLC garantiza que las medias de muchas Bernoullis son aproximadamente Normales. Para grupos chicos sería discutible y convendría una regresión logística; con n > 1.000 por grupo (como acá), ANOVA es perfectamente válida.
CÓDIGO COMPLETO · simulación de datos + ANOVA
Generar los 5.000 créditos individuales y testear
import numpy as np
import pandas as pd
from scipy import stats
from statsmodels.stats.multicomp import pairwise_tukeyhsd
np.random.seed(42) # reproducibilidad
sucursales = {
"Lima": {"n": 1500, "p": 0.025},
"Arequipa": {"n": 1200, "p": 0.027},
"Trujillo": {"n": 1100, "p": 0.031},
"Piura": {"n": 1200, "p": 0.030},
}
datos = {}
for nombre, info in sucursales.items():
datos[nombre] = np.random.binomial(1, info["p"], info["n"])
f_stat, p_anova = stats.f_oneway(*datos.values())
print(f"F = {f_stat:.3f}, p = {p_anova:.4f}")

DECISIONES TÉCNICAS
ANOVA sobre binarias, formato largo, Tukey vs Bonferroni
¿Por qué ANOVA sobre 0/1 (Bernoulli)?
Porque por el TLC, las medias muestrales de muchas Bernoullis son aproximadamente Normales. Con n > 1.000 por sucursal, la aproximación es excelente. Permite tratar la binaria como continua a efectos del test.
Alternativa más rigurosa: regresión logística con sucursal como predictor categórico. Pero introduce conceptos que no tocamos hasta Sesión 6. Para el propósito didáctico, ANOVA es más limpia.
¿Por qué armar el formato LARGO?
scipy.stats.f_oneway acepta lista de arrays (formato "ancho"). Pero statsmodels.pairwise_tukeyhsd exige formato LARGO: una columna con el valor, otra con el grupo. Ambos formatos son válidos en estadística; cada librería prefiere uno.
¿Por qué Tukey HSD y no Bonferroni?
Bonferroni divide α por el número de comparaciones (k). Es simple pero MUY conservador: para 6 pares, α se vuelve 0.05/6 = 0.0083. Tukey usa la distribución del rango studentizado, es exacto para ANOVA balanceado y más potente.
Cuándo Bonferroni gana: si las comparaciones son pre-especificadas (no todas vs todas) o si las muestras son muy distintas en tamaño. Para "todos contra todos" balanceado, Tukey.
¿Por qué ANOVA y no 6 t-tests entre pares?
Con 4 grupos hay 6 pares. 6 t-tests a α=0.05 cada uno tienen P(al menos 1 falso positivo) ≈ 26% (1 − 0.95⁶). ANOVA controla α en 5% para el TODO, y Tukey lo mantiene al ajustar los p-valores de cada par.

CASO 04 · CHI-CUADRADO DE INDEPENDENCIA

Una sola función responde todo, pero los residuos cuentan dónde rompe

El caso conceptualmente más simple del cuaderno: pasás una matriz de conteos, recibís un p-valor. Lo interesante viene después: los residuos estandarizados te dicen qué celdas específicas rompen la independencia. Es la pieza que separa el análisis básico del análisis útil.

Por qué este caso cierra bien la sesión. Chi² es el único test del cuaderno donde rechazar H₀ no te dice mucho por sí solo: "producto y default no son independientes" es vago. Los residuos estandarizados convierten ese rechazo en una historia accionable: "Consumo defaultea MÁS de lo esperado, Hipotecario MENOS".
CÓDIGO COMPLETO · Chi² de independencia
Matriz · función · interpretación
import numpy as np
import pandas as pd
from scipy import stats
# Tabla de contingencia OBSERVADA · sin totales
tabla_obs = pd.DataFrame(
data=[
[1850, 105], # Consumo
[1480, 20], # Hipotecario
[1390, 60], # Tarjeta
[ 95, 5], # Vehicular
],
index=["Consumo", "Hipotecario", "Tarjeta", "Vehicular"],
columns=["Al día", "En default"],
)
# Extraemos solo los valores (sin index ni columns) para scipy
matriz_obs = tabla_obs.values
chi2_stat, p_valor, gl, esperados = stats.chi2_contingency(matriz_obs)
print(f"χ² = {chi2_stat:.2f}") # → 19.34
print(f"gl = {gl}") # → 3
print(f"p = {p_valor:.6f}") # → 0.000234
CÓDIGO · RESIDUOS ESTANDARIZADOS
Dónde rompe la independencia
# Frecuencias ESPERADAS bajo H₀ (independencia)
tabla_esp = pd.DataFrame(esperados,
index=tabla_obs.index,
columns=tabla_obs.columns)
# Residuos estandarizados · regla |r| > 2 marca celdas relevantes
residuos = (matriz_obs - esperados) / np.sqrt(esperados)
tabla_res = pd.DataFrame(residuos.round(2),
index=tabla_obs.index,
columns=tabla_obs.columns)
print(tabla_res)
# Consumo / En default → r ≈ +3.8 (MÁS defaults de los esperados)
# Hipotec / En default → r ≈ -3.5 (MENOS defaults de los esperados)

Qué hace cada parte
FragmentoQué haceNota técnica
pd.DataFrame(data=[...], index=..., columns=...)Construye la tabla de contingencia con etiquetas legibles.No es estrictamente necesario para Chi², pero ayuda a debuggear y reportar. scipy solo necesita la matriz numérica.
matriz_obs = tabla_obs.valuesExtrae solo los valores numéricos (numpy array).chi2_contingency acepta DataFrame también, pero el array es lo "limpio" para pasarle.
chi2_contingency(matriz_obs)Calcula chi² automáticamente · sin pasarle "esperados" (los calcula sola).Devuelve TUPLA de 4 elementos: (chi2, p_valor, gl, matriz_esperados). El orden es fijo, no se puede invertir.

DECISIONES TÉCNICAS
Por qué chi2_contingency, por qué residuos estandarizados
¿Por qué chi2_contingency y no chi2 manual?
Podrías calcular χ² = Σ(O − E)²/E con un loop. La función te ahorra eso, te da gl correctos (filas-1)(cols-1), y te da las frecuencias esperadas listas para los residuos. Tres por uno.
¿Por qué residuos estandarizados y no residuos crudos?
Un residuo crudo (O − E) sin escalar no es comparable entre celdas: una celda con E=2000 y O=2050 (diff 50) parece grande, pero proporcionalmente es chica. Dividir por √E estandariza, dando valores en escala Normal estándar.
Variante: residuos AJUSTADOS estandarizados (corrigen por totales marginales). Más exactos pero más complejos. Para uso didáctico, los estandarizados clásicos son suficientes y la regla |r| > 2 funciona bien.
¿Por qué la regla |r| > 2?
Los residuos se distribuyen aproximadamente Normal estándar bajo H₀. La regla |r| > 2 corresponde aproximadamente al 5% de las colas (1.96 redondeado). Una celda con |r| > 2 es estadísticamente desviada de lo esperado.
¿Qué pasa si una celda tiene frecuencia esperada < 5?
El Chi² deja de ser fiable. En nuestro caso, la celda más chica (Vehicular default) tiene E ≈ 3.8 (al borde). Para tablas con muchas celdas chicas, usar test exacto de Fisher (scipy.stats.fisher_exact) en lugar de chi².
TIPS PARA EL AULA
Preguntas y errores típicos
PREGUNTA SOCRÁTICA
"¿Por qué los grados de libertad son 3 y no 8 (las celdas)?" Porque los totales por fila y por columna están FIJOS. Una vez que conocés 3 celdas (en una tabla 4×2), el resto queda determinado por los totales. gl = (filas − 1)·(cols − 1) = 3·1 = 3.
PREGUNTA SOCRÁTICA
"Si chi² rechaza H₀ pero ningún residuo es |r| > 2, ¿qué pasa?" Puede ocurrir cuando el efecto es la suma de muchas desviaciones chicas. Chi² agrega; los residuos miran celdas individuales. Si chi² rechaza, el efecto está; los residuos te dicen DÓNDE, pero a veces está repartido.
PREGUNTA SOCRÁTICA
"¿Por qué Vehicular con solo 100 créditos no inflas el chi²?" Porque chi² pondera cada celda por su esperado. Una celda chica contribuye poco al estadístico. Sin embargo, la frecuencia esperada baja hace que el test sea menos fiable: por eso reportamos al directorio enfocándonos en Consumo (donde sí hay n grande y residuo grande).
ERROR TÍPICO 1
Pasar la tabla con los totales (marginales) a chi2_contingency. Tira chi² inflado por cuenta doble. Verificá siempre que la matriz no tenga fila "Total" ni columna "Total".
ERROR TÍPICO 2
Interpretar "no son independientes" como "una causa la otra". NO. Chi² detecta asociación, no causalidad. Producto y default están asociados; eso no significa que el producto CAUSE el default (puede ser que clientes de mayor riesgo prefieran Consumo, por ejemplo).
ERROR TÍPICO 3
Olvidar revisar las frecuencias esperadas. Si alguna E < 5, el chi² puede dar un p-valor falso. Cómo prevenir: después de chi2_contingency, siempre imprimí esperados y revisá el mínimo.

Medir FUERZA de asociación · Cramer's V
cramers_v = np.sqrt(chi2_stat / (matriz_obs.sum() * (min(matriz_obs.shape) - 1))) # V ∈ [0, 1] · 0 sin asociación, 1 asociación perfecta
Chi² dice "hay asociación", Cramer's V dice "cuánta". Útil para reportes ejecutivos donde el directorio quiere un número entre 0 y 1.
